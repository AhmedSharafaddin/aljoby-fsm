# المعمارية — بسيط وقابل للتوسع

## جملة واحدة

تطبيق Next.js واحد (modular monolith) فوق PostgreSQL: الواجهات والـ API ومنطق الأعمال في مشروع واحد،
مفصولة بطبقات واضحة، بلا خدمات مصغّرة ولا وسيط رسائل.

## لماذا هذا الشكل

| القرار | السبب | متى نغيّره |
|---|---|---|
| مشروع واحد بدل خدمات متعددة | فريق صغير، نشر واحد، معاملات قاعدة بيانات بسيطة | عندما يحتاج جزء توسعًا مستقلًا فعلًا |
| PWA بدل تطبيق جوال أصلي | الفرق تثبّته من المتصفح فورًا، بلا متجر ولا مراجعة | عند الحاجة لعمل كامل بلا اتصال أو تتبع خلفي |
| منطق الأعمال في `modules/` لا في الصفحات | الـ API والصفحات وتطبيق جوال مستقبلي يستدعون نفس الدوال | — |
| الصلاحيات كنطاقات استعلام (`lib/permissions.ts`) | العزل يحدث في SQL نفسه؛ لا يمكن نسيانه في صفحة | — |
| الفروع من موقع الجوبي | aj-platform هو مالك بيانات الفروع؛ لا نكرّرها | — |
| مستودع منفصل عن aljoby-mobile وعن ووردبريس | بيانات التشغيل (عناوين العملاء، التواقيع) لا تُخزَّن على المتجر العام | — |

## الطبقات

```
app/                 الصفحات (Server Components) + app/api/v1 (مسارات رفيعة)
components/          ui.tsx (عرض) + client.tsx (نماذج، رفع صور، توقيع)
modules/             منطق الأعمال: orders, tasks, service, reports, rules
lib/                 core (قاعدة البيانات/الوقت/الهاتف/التدقيق), auth, permissions, api, storage, session, labels
prisma/              schema.prisma, migrations, seed.ts
tests/               rules.test.ts (وحدة), flow.test.ts (تكامل على قاعدة حقيقية)
```

الاتجاه واحد: `app` ← `modules` ← `lib`. مسار الـ API لا يحوي منطقًا؛ يحلل الطلب ويستدعي دالة من `modules`.

## قاعدة البيانات

الجداول في `prisma/schema.prisma` (التعليقات فيه هي المرجع). أهم القواعد:

- **ثلاث حالات منفصلة:** الطلب (`ServiceOrder.status`)، التكليف (`TaskAssignment.status`)، الرحلة (`DeliveryTrip.status`).
- **إعادة الإسناد لا تحذف:** التكليف القديم يصير `REASSIGNED` ويُنشأ جديد. السجل الزمني في `TaskEvent`.
- **رقم الطلب ورقم التذكرة** تسلسليان فريدان (`number`, `ticketNumber`). رقم الفاتورة **غير فريد** (فاتورة واحدة قد تولّد طلب تركيب وطلب توصيل) ومفهرس مع الفرع.
- **الصور والتوقيع** في جدول واحد `TaskFile` بحقل `kind` (BEFORE/AFTER/DELIVERY/SIGNATURE).
- **الكميات** `Decimal(10,2)`. الهدر يُحسب (المستلم − المستخدم) ولا يُخزَّن.
- **الوقت** UTC في القاعدة؛ «اليوم» والتأخير بمنطقة `APP_TZ` (افتراضيًا Asia/Aden).
- **التقييم** تقييم واحد لكل طلب (`orderId @unique`)، والرابط يُحفظ كبصمة SHA-256 فقط.
- **الجلسات** تُحفظ كبصمة أيضًا؛ تسريب نسخة من القاعدة لا يمنح دخولًا.

## سير الحالات

```
الطلب:   NEW → APPROVED → SCHEDULED → IN_PROGRESS → COMPLETED
          ↘ CANCELLED      ↘ ON_HOLD → APPROVED      ↘ ISSUE_REPORTED → IN_PROGRESS | SCHEDULED (إعادة إسناد)
الرحلة:  ASSIGNED → LOADED → DEPARTED → ARRIVED → DELIVERED   (خطوة واحدة في كل مرة)
الشكوى:  NEW → IN_PROGRESS → CONTACTED → RESOLVED → CLOSED    (للأمام؛ الرجوع للمدير العام مع سبب)
```

الجدول الكامل للانتقالات في `modules/rules.ts` (`ORDER_FLOW`). كل انتقال على الخادم يستخدم
`updateMany where status = الحالة_المقروءة` فيفشل بـ 409 إن سبقه تغيير متزامن.

**شروط الإتمام:** أثاث وموكيت: صورة قبل + صورة بعد + توقيع (والموكيت: الكميات). توصيل: توقيع، والإتمام بزر «تم التسليم».

**التأخير:** مقارنة `scheduledEnd` بوقت الإتمام الفعلي، أو بالآن إن لم يكتمل.

**اقتراح الفريق (`rankCandidates`):** للموعد المقترح (أقرب ساعة دوام 8–17): المحجوز يُستبعد، نفس المنطقة +3،
مكان شاغر +2، كل مهمة في نفس اليوم −1. يظهر مع أسبابه في قائمة الإسناد والقرار للمشرف.

**الموقع (`LocationPing`):** بضغطة من الموظف وإذن المتصفح، أثناء مهمة `IN_PROGRESS` مسندة له فقط، ويُحذف بعد
`LOCATION_RETENTION_DAYS` بمهمة cron يومية (`scripts/purge-locations.ts`). لا تتبع خلفي. رفض الإذن لا يعطّل شيئًا.

**التكاليف (`WorkCost`):** `amountMinor` عدد صحيح (لا float للأموال)، مربوطة اختياريًا بطلب/رحلة.

**منع التضارب:** عند الإسناد يُقفل صف الفريق/السائق (`SELECT … FOR UPDATE`) ثم تُعدّ التكليفات الفعالة المتداخلة؛ إن بلغت سعة الفريق يُرفض الطلب بـ 409.

| إنشاء طلب | ✓ | ✓ | — | ✓ (لفرعه) | — |
| اعتماد / إيقاف / إلغاء | ✓ | ✓ | — | — | — |

| تنفيذ المهمة | — | — | — | — | ✓ |
| الشكاوى | إدارة كاملة | إدارة كاملة | — | تسجيل ومتابعة لفرعه | — |
| رابط تقييم العميل | ✓ | ✓ | — | ✓ | — |

| مزامنة الفروع | ✓ | — | — | — | — |

السجل غير المرئي يُرجع **404** لا 403، فلا يكشف تغيير المعرّف في الرابط وجود الطلب.

## الأمن

- Argon2id لكلمات المرور، كوكي `HttpOnly; SameSite=Lax; Secure` (في الإنتاج)، والجلسات في القاعدة (إيقاف الحساب ينهيها فورًا).
- CSRF: SameSite=Lax + رفض أي طلب تعديل يحمل `Origin` من موقع آخر.
- تحديد المعدل لتسجيل الدخول ونموذج التقييم.
- الصور: حد 5MB، النوع من البايتات الأولى (JPG/PNG/WebP فقط)، خارج `public`، تُقدَّم عبر مسار يفحص الصلاحية مع `no-store`.
- `mapUrl` يقبل https فقط (لا `javascript:`)، وCSV محمي من حقن الصيغ.
- سجل تدقيق (`AuditLog`) لكل إنشاء/اعتماد/إسناد/إعادة إسناد/إيقاف/إلغاء/إتمام/تعديل شكوى/مستخدم.
- سجلات الأخطاء تحوي اسم الخطأ ورسالته فقط، لا محتوى الطلب.
